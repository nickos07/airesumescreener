# AI Resume Screener API

Backend API built with **FastAPI** that automatically analyzes the compatibility between a candidate's resume (PDF) and a job description (text), using the **Google Gemini API** to produce a structured analysis: matched skills, missing skills, a fit score, and reasoning.

Built as a portfolio project for a backend/AI engineering internship.

---

## Tech Stack

| Component | Technology |
|---|---|
| Language | Python |
| Web framework | FastAPI + Uvicorn |
| LLM | Google Gemini API (`google-generativeai`) |
| Data validation | Pydantic |
| PDF parsing | pypdf |
| Secrets management | python-dotenv |

---

## Architecture & Flow

1. The client sends a `multipart/form-data` request with a PDF file (`resume`) and text (`job_description`) to the `POST /screen-resume/` endpoint.
2. The PDF is read **entirely in memory** using `io.BytesIO`, following a cloud-native best practice: it avoids issues with ephemeral or read-only filesystems common in containerized/serverless environments.
3. Text is extracted from the resume using `pypdf`.
4. A prompt is built combining the resume text and job description, with explicit instructions telling the model **not to infer** skills or experience that aren't literally stated in the text (a hallucination-mitigation strategy).
5. Gemini (`gemini-3.5-flash`) is called using `response_schema`, forcing the model to return JSON that matches the `ScreenerResult` Pydantic schema exactly, rather than relying on the model to "choose" to format its response correctly.
6. The response is validated and parsed with `ScreenerResult.model_validate_json(...)` and returned to the client as JSON.

---

## Output Schema (`ScreenerResult`)

```python
class ScreenerResult(BaseModel):
    candidate_summary: str
    matched_skills: list[str]
    missing_skills: list[str]
    match_score_out_of_100: int
    reasoning: str
```

**Design decision:** `matched_skills` and `missing_skills` are **required fields that can be empty** (`[]`), rather than `Optional`. An empty list is a *valid, meaningful* result (the model determined there are no matches), whereas `Optional` would imply the field could be entirely absent — something that should never happen in a properly formed structured output.

## Error Handling

| Scenario | HTTP Code | Reason |
|---|---|---|
| `job_description` empty or too short (< 20 characters after `.strip()`) | `400 Bad Request` | Insufficient input for a meaningful analysis; rejected *before* calling Gemini to avoid wasting quota/cost on a useless request (*fail fast*) |
| File `content_type` other than `application/pdf` | `400 Bad Request` | A cheap first line of defense; it doesn't guarantee the file is actually a valid PDF, since `content_type` is declared by the client |
| Corrupted or invalid PDF (fails in `PdfReader`/`extract_text`) | `400 Bad Request` | The parsing exception is caught and translated into a clear client-facing error instead of a generic `500` |
| Failure calling Gemini (quota, network, invalid response) | `502 Bad Gateway` | The failure isn't the user's fault or an internal bug, but an external service dependency failing; the error message stays generic to avoid leaking internal details (API key, configuration) |

**Note:** the client-declared `content_type` can be inaccurate (e.g., a `.txt` file renamed to `.pdf` is reported by the browser as `application/pdf` based solely on the extension). That's why `content_type` validation is backed up by exception handling around the actual PDF parsing step.

## Technical Learnings & Discovered Edge Cases

- **Scanned PDFs (image-only, no text layer):** `pypdf` doesn't raise any error when processing them — it silently returns an empty string. This is a more dangerous "silent failure" than a crash, since the endpoint returns `200 OK` as if everything worked while quietly discarding the user's resume.
- **Irregular character spacing:** some PDFs (especially those generated by design tools) produce extracted text with spaces between individual letters (`Y A T S E N K O`). Real-world testing confirmed Gemini interprets this text correctly despite the noise, so no additional cleanup step was needed.
- **`content_type` isn't reliable as the sole validation:** it's declared by the client, not verified by the server, so it's used only as a fast filter, not a guarantee.
- **Module-level Gemini configuration:** `load_dotenv()` and `genai.configure()` run once at server startup (not inside the endpoint), avoiding redundant work on every request and allowing configuration errors (invalid API key, etc.) to be caught immediately at startup rather than on a real user's first request.

## How to Run

```bash
# 1. Create and activate a virtual environment
python -m venv venv
source venv/bin/activate      # macOS/Linux
venv\Scripts\activate         # Windows

# 2. Install dependencies
pip install fastapi uvicorn python-multipart google-generativeai pypdf pydantic python-dotenv

# 3. Set up environment variables
# Create a .env file in the project root with:
# GEMINI_API_KEY=your_api_key_here

# 4. Start the server
uvicorn main:app --reload
```

Interactive documentation (Swagger UI), auto-generated by FastAPI from the code, is available at:

```
http://127.0.0.1:8000/docs
```

## Example Usage

**Endpoint:** `POST /screen-resume/`
**Body (`multipart/form-data`):**
- `resume`: candidate's resume PDF
- `job_description`: job description text

**Example response:**

```json
{
  "candidate_summary": "The candidate is currently pursuing a degree in Artificial Intelligence at Universidad Carlos III de Madrid (UC3M). Their work experience consists of customer service roles in hospitality (waiter) and video editing, with no prior professional experience in AI or machine learning.",
  "matched_skills": ["Artificial Intelligence"],
  "missing_skills": ["Python", "Data Science", "Machine Learning"],
  "match_score_out_of_100": 70,
  "reasoning": "The candidate is a strong academic fit for an entry-level internship since they are explicitly studying Artificial Intelligence and the job requires no prior experience. However, while their degree program likely covers them, the resume text itself does not explicitly list Python, Data Science, or Machine Learning as skills, which are requested in the job description."
}
```
